# 面试讲解与代码阅读

## 三分钟讲法

> 我先做了一个双源文献检索与综述工作流，负责文献检索和工具整合。整理作品集时，又把它扩展为有证据引用的 PDF 问答助手。最大的改进是把“生成一段看起来像综述的文字”拆成可检查的检索、工具执行和引用验证步骤。
>
> 用户导入 PDF 后，系统逐页提取文字，切成 1200 字符、重叠 160 字符的片段，用内容哈希和页码生成稳定 ID，存到 SQLite。检索先用可解释、无需外部服务的 BM25；查询中的词和文档词频、逆文档频率共同决定得分。
>
> 问答时，模型通过原生 Function Calling 选择 search_library 或 get_page。程序负责校验参数、执行工具、记录轨迹。模型只能用 submit_answer 交付结论，每条结论必须附已取回片段的 ID 和原文引文。校验不通过时，把错误作为工具反馈交回模型，允许在预算内修正；超出 5 轮或 8 次调用就停止。
>
> 这个门禁能挡住不存在的文献编号和伪造原文，不能保证结论在语义上成立。我保留了人工核对入口，也没有把摘要证据当成全文证据。当前的离线演示用于验证工程链路，真实模型质量需要另建标注集评估。

按自己的真实理解复述。新增代码是 2026 年 10 月作品集升级，不要描述成 7 月实习期间已经完成。

## 五段代码，按顺序读

| 顺序 | 函数 | 输入 → 输出 | 要理解的设计取舍 |
| --- | --- | --- | --- |
| 1 | `Library.add_pdf` / `add_pages` | PDF 字节 / 页文字 → 文档 ID、片段 | 为什么保留页码；哈希如何防止重复导入 |
| 2 | `split_page` | 一页 → `(offset, chunk)` | 重叠能减轻边界截断；增加存储和重复证据 |
| 3 | `Library.search` | 问题 → 排序片段 | BM25 的 TF、IDF、长度归一化；中英分词局限 |
| 4 | `ResearchAssistant.run` | 问题、库 ID → 结论、引用、轨迹 | 模型决定调用什么；程序控制什么可以执行 |
| 5 | `validate_claims` | 结论、已取回片段 → 接受 / 抛错 | 原文存在与语义支持是两回事 |

## 一次请求的具体过程

1. API 校验问题长度、库是否存在。
2. 实例化模型适配器；离线替身和真实模型实现同一个 `turn(messages, tools)` 接口。
3. 模型返回 `search_library({query, limit})`，程序校验类型和上限。
4. BM25 返回前 K 个片段；片段进入本次请求的 evidence 字典。
5. 模型可改写关键词再次检索，或对已检索到的文献调用 `get_page`。
6. `submit_answer` 只接受每条结论附引用的结构。未知 ID、伪造引文或缺引用会被拒绝。
7. 返回接受的结论与来源信息，前端展示文献、页码、引文，支持下载 JSON。

## 常见追问

**几个智能体怎么通信？**

同进程的中心协调器维护 SQLite 共享工作区，产物通过 Pydantic 契约交接。每个产物记录角色、上游 artifact ID、资料版本和引用；下游请求包含真实上游内容。交接事件用于查看输入输出。研究阶段由程序安排，PDF 问答内部再由模型选择工具。具体阅读 `coordination/contracts.py` → `workspace.py` → `tests/test_coordination.py`。

**这到底是 Agent 还是 Workflow？**

原跨库检索与综述模块是固定工作流。新增 PDF 问答模块由模型在多轮中选择检索、翻页和结束动作，是范围有限的工具调用 Agent；不能任意规划外部研究，也不执行 Python、Shell 或浏览器操作。

**为什么不用 LangChain / LangGraph？**

当前只有三个工具和小规模状态，显式循环更容易解释预算、错误和证据流。未来需要复杂分支、持久检查点和人工审批时，再评估图框架；当前没有框架使用经验的事实就不写进简历。

**为什么先用 BM25？**

成本低、无需 Key、便于建立可重复基线。局限是同义表达和跨语种召回弱。下一步应在同一标注问题集上比较向量检索、BM25 与 RRF 混合检索，不能仅凭“上了向量库”宣称更好。

**如何评估？**

工程层：页码、去重、空库、坏 PDF、越权库混用、未知工具、超预算、伪造引文。检索层：人工标注相关片段，测 Recall@K / MRR。答案层：人工评估正确性、引用是否支持结论、无依据断言比例和拒答合理性，并记录延迟 / Token / 成本。仓库当前测试只覆盖工程契约，未声称真实模型达到某个准确率。

**提示注入怎么处理？**

资料被标记为不可信数据；工具白名单、参数校验和库范围限制缩小可执行范围。它们不是“完全防注入”的证明。攻击可能仍影响回答内容，后续需要专门红队样例和服务端身份认证。
